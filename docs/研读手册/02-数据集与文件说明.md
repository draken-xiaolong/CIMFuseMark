# 02 数据集与文件说明

## 1. 数据来自哪里

最终论文只使用日本国土交通省Project PLATEAU的CityGML建筑数据，数据年份覆盖2022—2025。没有把香港、美国OCM或李老师内部数据混入最终主实验。

论文使用10个地区，并按城市隔离划分：

| 划分 | 城市/地区 | GML瓦片 | 建筑 |
|---|---|---:|---:|
| 训练 | 东京千代田、东京港、东京新宿、埼玉 | 47 | 369 |
| 验证 | 横滨、川崎 | 32 | 256 |
| 测试 | 大阪、福冈、广岛、仙台 | 64 | 512 |
| 合计 | 10个地区 | 143 | 1,137 |

这种划分比随机拆分建筑更严格。测试城市从未参与训练，避免相邻建筑或同一源文件泄漏到训练和测试两边。

## 2. 为什么有约14 GB

移动硬盘数据根目录：

`/Volumes/SANDISK-ELE/CIMFuseMark/CIMFuseMarkData`

当前总量约14 GB，主要构成为：

| 子目录 | 大小约 | 内容 |
|---|---:|---|
| `data/` | 13 GB | 原始PLATEAU数据、解压缓存和实验瓦片 |
| `data/plateau_multicity_archives/` | 12 GB | 官方下载的`.zip`压缩包 |
| `data/plateau_multicity_cache/` | 1.0 GB | 从压缩包选择出的建筑主题源`.gml` |
| `data/plateau_multicity_tiles/` | 388 MB | 最终143个实验`.gml`瓦片 |
| `results/` | 381 MB | 训练/攻击/消融结果JSON和部分图表 |
| `checkpoints/` | 131 MB | 历史模型检查点 |
| `metadata/` | 28 MB | 数据清单与审计信息 |

真正每次训练需要读取的核心数据不是全部13 GB，而是约388 MB的`plateau_multicity_tiles`。12 GB压缩包主要用于可追溯和重新生成。

## 3. 三层数据的区别

### 第一层：官方下载包

- 后缀：`.zip`
- 体积：约12 GB
- 作用：保留PLATEAU官方原始发布包，便于核验和重新抽取。
- 是否直接训练：否。

### 第二层：选择出的源CityGML

- 后缀：`.gml`
- 体积：约1 GB
- 作用：从每个城市压缩包中选择建筑主题文件。
- 是否直接训练：通常否，文件仍然较大。

### 第三层：实验瓦片

- 后缀：`.gml`
- 数量：143个
- 体积：约388 MB
- 规则：通常每8栋Building组成一个tile。
- 是否直接训练：是。

切片的目的不是改变建筑，而是把超大城市文件拆成显存和训练时间可控的“小型城市片段”。

## 4. manifest是什么

关键清单文件：

`code/data/plateau_multicity_manifest.json`

它像数据集目录，记录：

- 每个源数据的城市、年份、URL、SHA-256；
- 每个瓦片属于train、validation还是test；
- 瓦片相对路径；
- 建筑数、边界对象数、语义类型计数；
- 数据集总计和城市划分。

一个条目大致如下：

```json
{
  "id": "chiyoda_53394519_tile_000",
  "region": "Tokyo Chiyoda",
  "split": "train",
  "path": "plateau_multicity_tiles/train/...gml",
  "building_count": 8,
  "boundary_count": 551
}
```

训练脚本先读manifest，再根据`split`选文件。这样数据划分不是临时随机决定，而是固定、可检查的。

## 6. 常见文件后缀

| 后缀 | 示例用途 |
|---|---|
| `.zip` | PLATEAU原始下载包 |
| `.gml` | 原始、切片或受攻击CityGML |
| `.json` | manifest、配置、训练报告、攻击曲线 |
| `.pt` | PyTorch模型检查点 |
| `.csv` | 论文表格对应的扁平数据 |
| `.pdf/.png/.svg/.tiff` | 论文图与最终论文 |
| `.tex/.bib` | LaTeX论文正文和参考文献 |

## 7. 代码仓库为何不放大数据

Git仓库只保存代码、小型配置、必要汇总结果和文档。原始压缩包、完整攻击缓存和模型检查点放移动硬盘，因为：

- Git不适合存十几GB二进制文件；
- `.zip`和`.pt`每次变化都会形成大版本；
- 数据可以通过固定URL和SHA-256重新下载/验证；
- 论文复现需要的是下载脚本、manifest和参数，而不是把原始数据提交到Git。
